## 2. 결측 · 이상값

- [ ] **컬럼별 결측(NaN) 비율** — 어떤 컬럼이 얼마나 비어있나?
- [ ] **타겟의 결측** — 예측 대상(BOW)이 비어있는 행은 몇 개? (학습 불가)
- [ ] **이상값 범위** — 각 컬럼 min/max가 상식적인가? (음수 온도, 0인 길이 등)
- [ ] **중복 행** — 완전히 같은 행이 있는가?
- [ ] ⚠️ **단위 중복** — 한 대상이 여러 행으로 쪼개져 있는가? (이 프로젝트: wafer 단위 중복 → lot 단위 재집계 필요)

## 3. 타겟 변수 (예측 대상)

- [ ] **타겟 분포** — 히스토그램. 정규분포인가, 치우쳤는가?
- [ ] **타겟 표준편차** — 산포가 큰가? (이 프로젝트: BOW std ≈ 0.9로 큼)
- [ ] **타겟 범위** — 스펙(양품 기준)과 비교. 대부분 스펙 안인가 밖인가?
- [ ] **타겟이 여러 개인가** — total 말고 seed/mid/tail 등. 어느 걸 예측할지
- [ ] ⚠️ **예측 가능성의 상한 추정** — 같은 조건인데 타겟이 다른 정도. 이게 크면 아무리 좋은 모델도 한계 (재현성 진단)

```python
df['target'].hist()
print(df['target'].std(), df['target'].min(), df['target'].max())
# 유사 조건 쌍의 타겟 차이 → 노이즈 하한 추정
```

## 4. Feature 성격 분류 ⚠️ (이 프로젝트에서 가장 중요했던 부분)

각 feature를 반드시 아래로 분류:

- [ ] **제어 가능 vs 불가** — 엔지니어가 바꿀 수 있는 값(recipe)인가, 주어진 조건인가?
- [ ] ⚠️ **측정 시점** — 가공 **전**에 아는 값인가, 가공 **후**에 나오는 값인가?
  - 사후 값(post-measurement)을 feature로 쓰면 **leakage**. 배포 시엔 알 수 없음
  - 이 프로젝트: `range_wire_guide`가 사후값 → 제외해야 했음
- [ ] **파생값 여부** — 원본인가, 다른 값에서 계산된 것인가? (예: range = 차이값 → 부호 소실)
- [ ] **recipe 후보** — 추천해야 할 대상은 원본 설정값이어야 함 (파생값은 역산 불가)

```python
# 각 컬럼을 표로: 컬럼명 | 제어가능? | 측정시점(전/후) | 원본/파생
```

## 5. 시간 구조 ⚠️

- [ ] **날짜 컬럼 존재/범위** — 기간이 언제부터 언제까지?
- [ ] **시간순 정렬 가능한가** — run/lot 순서를 알 수 있나?
- [ ] ⚠️ **train/test 시간 분할 가능한가** — 랜덤 분할은 성능을 부풀림. 배포는 "과거→미래"라 시간 분할이 진짜
- [ ] **시간에 따른 분포 변화** — 앞 기간과 뒤 기간의 값 분포가 다른가? (분포 이동)
- [ ] ⚠️ **자기상관** — 연속된 행(같은 장비/wire)의 타겟이 비슷한가? 직전 값을 feature로 넣으면 leakage 가능

```python
df['date'] = pd.to_datetime(df['date'])
print(df['date'].min(), df['date'].max())
# 앞 50% vs 뒤 50% 타겟 평균·분산 비교
```

## 6. 그룹 구조 ⚠️ (Simpson's Paradox 방지)

- [ ] **개체(장비/설비) 컬럼** — 여러 장비/설비가 섞여 있는가?
- [ ] ⚠️ **개체별 타겟 레벨 차이** — 장비마다 평균 타겟이 다른가?
  - 다르면 전체 상관이 왜곡됨 (Simpson's Paradox)
  - 이 프로젝트: 온도-BOW 상관이 전체 +0.09 → 장비 내 −0.15 (부호 반전!)
- [ ] **개체 내 상관 vs 전체 상관** — 둘을 따로 봐야 함
- [ ] **개체 식별자 처리** — one-hot? 중심화? (이 프로젝트: 장비 one-hot 필수)

```python
# 전체 상관
print(df[['feature','target']].corr())
# 장비별(개체별) 상관 → 부호가 전체와 다른가?
for eqp in df['eqp'].unique():
    sub = df[df['eqp']==eqp]
    print(eqp, sub['feature'].corr(sub['target']))
```

## 7. Train/Test 분리 정합성 ⚠️

- [ ] **train과 test에 같은 개체가 겹치나** — 검증이 낙관적으로 편향될 수 있음
- [ ] **test 기간이 train 기간과 겹치나** — leakage 위험
- [ ] ⚠️ **검증용 데이터의 특수 조건** — test가 특정 실험 조건(변경군/대조군)인가?
  - 이 프로젝트: test 8대의 특정 기간만 제외해야 했음
- [ ] **컬럼이 train/test 모두에 있나** — test엔 없는 컬럼을 학습에 쓰면 배포 불가

```python
train_eqps = set(train['eqp']); test_eqps = set(test['eqp'])
print('겹치는 장비:', train_eqps & test_eqps)
print('train에만:', set(train.columns) - set(test.columns))
```

## 이 프로젝트에서 실제로 터졌던 것들 (교훈)

| 놓쳤던 것 | 증상 | 확인했다면 |
| :--- | :--- | :--- |

| Simpson's Paradox | 계수 부호가 공정 지식과 반대 | #6 개체별 상관 |

| 컬럼명 불일치 | Trend 안 그려짐 | #1 컬럼명 |
| wafer 중복 | R² 부풀림 | #2 단위 중복 |

**핵심 교훈**: 모델을 돌리기 전에 데이터를 충분히 이해하면, 위 6개 중 대부분을 처음부터 피할 수 있었음. "높은 R²"가 나오면 기뻐하기 전에 leakage부터 의심할 것.
